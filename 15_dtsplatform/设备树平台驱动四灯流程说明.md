# 15_dtsplatform 四灯设备树平台驱动流程说明

本实验是标准设备树 platform 驱动写法。驱动不再单独注册 `platform_device`，而是依靠设备树节点的 `compatible` 自动匹配。

当前设备树父节点：

```dts
gpio-leds {
	compatible = "lhb,gpio-leds";
	pinctrl-names = "default";
	pinctrl-0 = <&gpio_leds_gpio>;
	status = "okay";

	led0 {
		label = "led0";
		gpios = <&gpio1 RK_PB0 GPIO_ACTIVE_HIGH>;
		default-state = "off";
	};

	led1 {
		label = "led1";
		gpios = <&gpio1 RK_PA7 GPIO_ACTIVE_HIGH>;
		default-state = "off";
	};

	led2 {
		label = "led2";
		gpios = <&gpio0 RK_PC6 GPIO_ACTIVE_HIGH>;
		default-state = "off";
	};

	led3 {
		label = "led3";
		gpios = <&gpio0 RK_PA0 GPIO_ACTIVE_HIGH>;
		default-state = "off";
	};
};
```

驱动匹配表：

```c
static const struct of_device_id led_of_match[] = {
	{ .compatible = "lhb,gpio-leds" },
	{ }
};
```

## 代码流程

1. 加载 `leddriver.ko`。

   驱动通过 `module_platform_driver()` 注册到 platform 总线。

2. 内核根据设备树自动匹配。

   内核扫描设备树中的 platform 设备，发现 `gpio-leds` 节点的 `compatible` 是 `lhb,gpio-leds`，和驱动的 `of_match_table` 一致，于是调用 `led_probe()`。

3. `led_probe()` 获取设备树节点。

   标准设备树 platform 驱动不需要 `of_find_node_by_path()`，直接使用：

   ```c
   pdev->dev.of_node
   ```

4. 遍历 4 个 LED 子节点。

   驱动通过 `for_each_available_child_of_node()` 遍历 `led0` 到 `led3`。

5. 解析每个 LED 的 GPIO。

   每个子节点通过：

   ```c
   of_get_named_gpio_flags(child, "gpios", 0, &gpio_flags)
   ```

   获取 GPIO 编号和 `GPIO_ACTIVE_HIGH` / `GPIO_ACTIVE_LOW` 信息。

6. 初始化 GPIO。

   驱动依次调用：

   - `gpio_request()`
   - `gpio_direction_output()`

   初始状态统一设置为关闭。

7. 注册字符设备。

   驱动创建 `/dev/dtsplatled`。

8. 用户态控制 LED。

   `ledApp` 向驱动写入 2 个字节：

   - 第 1 个字节：LED 编号，范围 `0~3`
   - 第 2 个字节：LED 状态，`0` 关闭，`1` 打开

9. 卸载驱动。

   `led_remove()` 销毁 `/dev/dtsplatled`，注销字符设备，关闭并释放所有 GPIO。

## 编译

```sh
make
```

或：

```sh
make build
```

生成：

- `leddriver.ko`
- `ledApp`

## 使用

加载驱动：

```sh
insmod leddriver.ko
```

控制 LED：

```sh
./ledApp /dev/dtsplatled 0 1
./ledApp /dev/dtsplatled 0 0
./ledApp /dev/dtsplatled 1 1
./ledApp /dev/dtsplatled 2 1
./ledApp /dev/dtsplatled 3 1
```

卸载：

```sh
rmmod leddriver
```

## 和 14_platform 的区别

`14_platform` 需要手动加载 `leddevice.ko`，设备和驱动靠名字 `rk3588-led` 匹配。

`15_dtsplatform` 不需要 `leddevice.ko`。设备来自设备树，驱动靠 `compatible = "lhb,gpio-leds"` 自动匹配。
