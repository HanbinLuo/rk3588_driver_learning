# 14_platform 四灯平台驱动流程说明

本实验保留传统 platform 的“设备和驱动分离”结构：

- `leddevice.ko` 注册一个 `platform_device`，名字是 `rk3588-led`。
- `leddriver.ko` 注册一个 `platform_driver`，名字也是 `rk3588-led`。
- 内核根据 `.name` 完成匹配，匹配成功后调用 `led_probe()`。
- `led_probe()` 再读取当前设备树 `/gpio-leds` 节点，初始化 4 个 LED GPIO。

当前设备树节点格式：

```dts
gpio-leds {
	compatible = "lhb,gpio-leds";
	status = "okay";

	led0 {
		label = "led0";
		gpios = <&gpio1 RK_PB0 GPIO_ACTIVE_HIGH>;
		default-state = "off";
	};

	led1 {
		label = "led1";
		gpios = <&gpio1 RK_PA7 GPIO_ACTIVE_HIGH>;
		default-state = "off";
	};

	led2 {
		label = "led2";
		gpios = <&gpio0 RK_PC6 GPIO_ACTIVE_HIGH>;
		default-state = "off";
	};

	led3 {
		label = "led3";
		gpios = <&gpio0 RK_PA0 GPIO_ACTIVE_HIGH>;
		default-state = "off";
	};
};
```

## 代码流程

1. 加载 `leddevice.ko`。

   `leddevice.c` 调用 `platform_device_register()` 注册一个名字为 `rk3588-led` 的 platform 设备。

2. 加载 `leddriver.ko`。

   `leddriver.c` 使用 `module_platform_driver()` 注册 platform 驱动，驱动名同样是 `rk3588-led`。

3. 内核完成名字匹配。

   设备名和驱动名一致后，内核调用 `led_probe()`。

4. `led_probe()` 解析设备树。

   驱动通过 `of_find_node_by_path("/gpio-leds")` 找到父节点，然后检查：

   - `status = "okay"`
   - `compatible = "lhb,gpio-leds"`

5. 遍历 LED 子节点。

   驱动使用 `for_each_available_child_of_node()` 遍历 `led0` 到 `led3`，每个子节点通过 `of_get_named_gpio_flags(child, "gpios", 0, &gpio_flags)` 获取 GPIO 和有效电平。

6. 初始化 GPIO。

   每个 LED 都会执行：

   - `gpio_request()`
   - `gpio_direction_output()`
   - 默认输出关闭电平

7. 注册字符设备。

   驱动创建 `/dev/platled`，用户态通过它控制 4 个 LED。

8. 用户态写入控制命令。

   `ledApp` 写入 2 个字节：

   - 第 1 个字节：LED 编号，范围 `0~3`
   - 第 2 个字节：LED 状态，`0` 关闭，`1` 打开

9. 卸载驱动。

   `led_remove()` 销毁 `/dev/platled`，注销字符设备，关闭并释放所有 GPIO。

## 编译

```sh
make
```

或：

```sh
make build
```

生成：

- `leddevice.ko`
- `leddriver.ko`
- `ledApp`

## 使用

先加载设备，再加载驱动：

```sh
insmod leddevice.ko
insmod leddriver.ko
```

控制 LED：

```sh
./ledApp /dev/platled 0 1
./ledApp /dev/platled 0 0
./ledApp /dev/platled 1 1
./ledApp /dev/platled 2 1
./ledApp /dev/platled 3 1
```

卸载：

```sh
rmmod leddriver
rmmod leddevice
```

## 和 15_dtsplatform 的区别

本实验的 platform 匹配依赖 `leddevice.ko` 和 `leddriver.ko` 的名字相同，也就是 `rk3588-led`。

设备树这里只负责提供 GPIO 信息，驱动不是靠 `compatible = "lhb,gpio-leds"` 自动匹配进来的。
